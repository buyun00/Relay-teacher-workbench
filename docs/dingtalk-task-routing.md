# 钉钉单聊天中的独立任务

钉钉私聊增加任务分流层：DeepSeek 先判断消息属于新任务、已有任务、状态查询、交付重试还是待澄清事项。确定归属后，原钉钉模型分类器只接收目标任务的历史；PPT 和教学视频继续使用现有制作流程，其他任务使用独立的原生 Hermes 会话和工作目录。

教师客户端的 `Chats`、分类规则、固定模型、桌面数据库表和发布流程均不参与此入口。没有修改 Hermes 核心或增加授权钩子；入口仍放在现有插件的授权判断之后，仅处理钉钉私聊。

## 使用行为

- 制作 PPT 时可以继续问生活问题或提出图片、视频需求；独立事项创建独立任务。
- “刚才函数 PPT 第二页加个例子”回到该任务；同一任务尚在执行时，补充按入站顺序排队。
- “颜色淡一点”存在多个可能目标时先询问，原请求和附件保留。回答任务名称后继续处理原请求，不把选择答案当作全部需求。
- “现在有哪些任务”、`/tasks` 或“任务列表”读取代码保存的状态，不由模型编造进度。
- `/new`、`/reset`、“新对话”或“换个话题”只清除当前话题指向，不停止其他任务。
- 结果使用任务名称标注；后台完成通知不会更改正在讨论的话题。
- 文件发送失败时指定任务“重发”，只发送未成功的文件与保存的正文，不重复制作。交付失败期间不接受该任务的新修改，以免覆盖待交付版本。
- 连续发送的纯照片、纯文件先进入同一待用素材批次并保存，不调用 DeepSeek、不新建任务、不开始制作。钉钉自动补出的“[文件] 文件名”也按素材处理；附带实际文字要求的消息可以正常分流。
- 上传完后说“根据上面的图片制作 PPT”，程序才把批次和要求一起放入目标任务。只问晚餐、天气、状态或提出不使用这些素材的新需求时，批次继续保留；用途有歧义时先澄清，原始要求和素材都保留。
- 同一批次只发一次接收提示。待用素材可在任务列表中看到数量；`/new` 不清除素材。下载失败可回复“继续使用这些素材”重试，已经保存的素材无需再次下载；不会以接收提示冒充文件保存完成。

任务调度默认最多同时执行 3 个任务；同一任务只有一条执行中的消息。附件下载使用独立的准备队列，不占用制作名额，也不会让后续同任务消息插队。ASR/TTS/GPU 的资源排队仍由原服务负责，这里不承诺物理计算资源无限并行。

## 数据和恢复

运行数据位于现有 `smart-chat/task-routing/`，不进入仓库：

- `tasks.sqlite`：来源身份、任务目录、当前话题、待澄清消息、入站队列、回复关联、执行与交付状态。
- 每个任务独立的原生 SessionDB 会话 ID 和 `native_tip`（保存为 `hermes_session`）。
- `<task_id>/input/`、`output/` 与逐轮请求、回复和进程错误记录。
- `_materials/<batch_id>/input/`：待用素材原件；批次和入站消息关联也保存在 SQLite。指定用途后，按入站顺序复制到对应任务，不给生活问答或其它用户携带。重启继续未完成的素材接收，已经执行的制作不会因此重做。

路由模型不能自行分配真实任务 ID，也不能把消息指向其他用户或聊天。旧钉钉话题按原 ID 一次性导入，保留原生会话和制作会话引用；新任务不复制旧历史、附件或模型状态。

入站消息 ID 幂等，同 ID 不同内容拒绝处理。分流失败不会落入旧的共享聊天执行。热加载通过 gateway 对象保存运行时、锁和正在运行的协程。进程重启后，不自动重复执行曾处于运行中的任务；保存的生成结果和文件回执恢复为待交付。普通排队工作在下一次入站唤醒调度器后继续；中断任务需用户明确继续。

每个通用任务运行于自己的 Hermes 子进程，避免 `cwd`、环境变量和工具上下文在协程间混用。会话恢复使用原生 SessionDB；历史缺失时明确失败。原生回复结束、文件生成、文件发送和教师业务完成是不同层次，教学业务完成规则仍由原 Store 决定。

通用任务通过 Hermes 原生 `skip_memory` 和工具集选项关闭全局记忆的自动注入与写入；不会把制作需求写成其他任务的长期偏好。按用户确认共享偏好可作为后续独立功能，当前没有改动教师客户端的记忆配置。

卡片使用已有主动发送链路，不依赖长任务结束时已经过期的入站 webhook。文件发送必须收到钉钉文件消息回执，已发送部分持久化后才继续发送其他文件。

## 引用回复的边界

若原生 `MessageEvent.reply_to_message_id` 提供已知消息 ID，会优先命中持久化回复映射，模型不能改投其他任务。当前钉钉适配器的入站构造未显式填入该字段，所以手机实际“引用卡片”是否返回可用 ID 仍需真机验证，不能把合成事件测试当作已验证的平台能力。直接说任务名称与歧义澄清不依赖该字段。未实现卡片按钮或修改钉钉平台适配器。

## 安装与回滚

此次候选只增加两个插件模块，并修改现有插件的钉钉入口；不安装桌面端，不构建客户端安装包。

先在可读的实时插件副本上检查兼容性：

```sh
python ops/install_task_routing.py --router /opt/data/plugins/smart-chat-router --source workbench
```

脚本默认只检查。要求已存在教学视频分流和带文件回执的原对话交付扩展；代码锚点不一致则停止，不覆盖未知版本。

首次应用前确认旧钉钉聊天没有执行中的普通模型轮次，等待旧 PPT/视频及交付结束。脚本会拒绝在 `native-classroom` 仍有 active/delivering 状态时首次安装。

```sh
python ops/install_task_routing.py --router /opt/data/plugins/smart-chat-router --source workbench --apply
```

安装前备份到 `teacher-plugin-backups/task-routing-<timestamp>`；写入异常回滚本次文件。然后使用原生 `reload-plugins` 控制接口加载，仅刷新插件，不重启 Hermes、教师接收端、ASR 或 TTS。若回滚，应先等新任务停止执行，将备份的入口恢复并热加载；保留任务数据库、文件和原生会话供恢复，不删除业务数据。
