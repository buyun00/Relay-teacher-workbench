# 录音整理与确认入库

录音接收后沿用原有 ASR；默认 `recording_output=organization`。原生 Hermes 用 `teacher_organize context` 读取本文件及同日相邻文件的转写、课表和已有草稿，再用 `propose` 保存活动。它可以把半小时文件合并为课程，也可以把一个文件拆成多个活动。所有当前转写片段须归入活动才算分析完成；工作流租约、来源版本与数据库事务决定完成状态，模型答复不算完成。

活动先存在 `recording_activities`，上传或完成分析都不会创建已确认课次。活动只把最多三个关键歧义设为问题，其余记录默认折叠。界面从转写直接显示目标原句及前后文，同时显示原文件相对时间和可确定的录制时刻。

录制开始时间只从可识别的 `YYYYMMDD_HHMMSS` 文件名读取，不拿文件修改时间冒充上课时间。无法确定时显示未知。每周课表按星期、开始时间相差不超过十分钟及主要时段重合匹配；只有唯一候选的课堂活动自动预选班级。谈话不强行套用课表。教师手动指定的班级不会被后来修改的课表覆盖。

说话人选择点击即变为搜索输入框。前端对当前班级名单预建姓名、无声调全拼和首字母索引，每次输入立即本地筛选；不逐字调用网络。支持中文、姓氏读音、键盘上下选择、Enter 确认、Escape 关闭与输入法组合。学生 ID 与解释内容分离，跨班级选择被服务端拒绝，匿名标签只在原录音内有效，不能因同一标签跨录音自动实名。记不清可保留未知。

教师可以选择学生或教师角色，也可以针对一个片段保存补充。所有修改都使用版本号，追加教师消息及更正历史。确认入库在同一事务中创建 `lessons`、对应录音范围和 `events`；重新点击不会重复创建。此后 `teacher_query` 可以查询这些记录。历史按日期倒序、同日按时间正序排列，显示日期、课次、班级和起止时间。入库后的更正同步有效事实并使相关产物过期，不删除原始转写或最初的分析草稿。原生对话中的事实更正也使旧界面的编辑版本失效。

接口：`GET /v1/organization` 读取名单、课表和活动；`POST /v1/organization` 提交 `class`、`resolve`、`note`、`publish`、`schedule`。复用现有接收端的凭据和教师空间校验。凭据仅在 Electron 主进程中使用。未连接、保存失败或版本冲突会报错，不显示入库成功。浏览器预览明确使用虚构数据，Electron 从真实接收端读取。

旧版 `brief/preparation` 处理可通过 `recording_output=reports` 保留，旧产物读取接口不变。新整理页面不生成教学发现、跟进建议或复盘报告。

部署要同时更新接收端 Python 源码与 `plugin.yaml` 中的 `teacher_organize` 工具声明，重启本项目的录音接收服务；不重启 Hermes 容器或其他服务。数据库迁移只新增表和触发器，旧客户端的上传、聊天与产物接口继续可用。Windows 客户端通过 GitHub Actions `npm run pack:win` 交付安装包及内容更新。

验证分层：Python 测试使用虚构转写，覆盖完整来源、合并、课表、身份、确认、版本冲突、更正、删除和恢复；Playwright 覆盖逐字搜索和最小窗口；Electron/打包 EXE 测试实际文件上传、IPC、HTTP、SQLite、确认入库、历史、更正与重启保留。该合成测试不代表真实 ASR 精度、麦克风现场识别或课堂验收。
