# 原对话成品交付

这是强制交付要求：用户要求制作或修改的文字成果直接给出完整正文；所有文件成品在发起任务的原对话直接发送实际附件。视频、PPT、文档、表格、图片、音频、网页文件、代码、压缩包和其它格式同样适用。地址、链接和服务器路径只能补充，后台制作也不能要求用户再次索取成品。

`workbench/delivery_policy.py` 保存统一规则及成品收集逻辑。教师插件用原生 system prompt section 和每轮上下文注册规则；桌面执行器还指定当前会话的 `output/` 目录。只自动收集本轮改变的成品，旧文件需要明确声明才能再次交付；最终回复可逐个使用 `MEDIA:"绝对文件路径"` 声明文件。文件复制、原对话附件登记和事件持久化由代码负责，已有文件不重新计算哈希。

桌面附件保存在同一个教师 Store，并随原回复、快照、重连和业务备份保留。后续修改工作副本不会改写历史附件。浏览器的普通链接不能替代 Electron 文件下载接口。

钉钉使用已有 `smart-chat-router` 插件的文件上传和原接收人发送接口。`workbench/gateway_delivery.py` 将此能力接到普通对话的原生媒体发送方法；每轮来源由已有授权入口绑定，发送结果必须含文件消息回执。独立 PPT/视频流程先发成品，再封口最终卡片；失败持久化为 `delivery_failed`，回复“重发”只尝试未成功发送的文件，保留已制作的文件和已成功发送的版本。文件名、修改时间和长度用于识别本轮文件版本，不作教学来源哈希复核。

部署时先用 `scripts/build_bundle.py` 构建教师插件并备份线上插件和 Store。仅更新本项目插件与接收端代码；在 Hermes 容器中执行 `ops/install_chat_delivery.py --router /opt/data/plugins/smart-chat-router --source <teacher-plugin>/workbench` 更新已有路由插件。脚本先校验当前插件的代码锚点并编译候选，代码发生漂移时停止；旧文件备份到 `teacher-plugin-backups/delivery-*`。它不修改 Hermes 核心、宿主版本或平台配置，不重启 Hermes、ASR 或 TTS。路由插件通过原生 `reload-plugins` 控制接口热加载；教师接收端在没有正在运行的轮次时更新自己的进程。

虚构字节和模拟钉钉回执测试可证明附件持久化、HTTP 下载、原对话隔离、失败状态、重发和最终卡片顺序，不能证明 PPT 视觉质量、真实视频播放或实际钉钉收件。交付过程意外中断时保留成功回执，下一轮“重发”继续发送剩余文件，不重复制作。

2026-10-13 使用虚构 QA 空间、原生 Hermes 的 GPT-6 Sol 和包含模块热更的打包 EXE 完成实际验收：模型用文件/终端工具生成 TXT 与 PNG，两个文件直接显示在原回复附件区；原生图片预览与保存接口有效，保存字节与服务器附件一致；退出重开后原对话、原生 session 和成品附件保留。未发送真实钉钉测试消息，未据此宣称 PPT 或视频内容验收通过。

桌面交付同时运行 `npm run pack:local`，本地安装包保存在忽略的 `uploader/release-local/`，关闭 GitHub 自动更新；官方发布仍使用 `npm run pack:win`。
