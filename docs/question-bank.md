# 服务端题库

题库复用 Hermes 教师插件的 Store、SQLite 和文件目录。数据库位于服务器的 `teacher-workspaces/teacher/database/workbench.sqlite`；EXE 不持有题库数据库。真实题目、导出原件、学生信息和运行产物不进入代码仓库。

## 桌面页

主界面独立的“题库与作业”卡片进入题库。支持批次、文字、知识点、题型、审核状态筛选和分页；详情展示 MathML、题图、答案解析、缺失警告和修订来源。改编另存为派生题，核对操作生成新版本。选题篮可为每题填写任务、提示和教师依据，绑定名册学生或保存通用草稿。草稿可查看学生版/教师版并导出可打印 HTML；过期草稿禁止导出。

Electron 主进程复用现有凭据访问 `POST /v1/question-bank`，渲染进程不接触连接凭据。接口复用原有教师空间校验和 Store。页面预览采用不运行脚本、不访问网络的沙箱 iframe。浏览器开发预览只有明确标识的虚构数据，不连接生产题库。文件导出仅保存作业文件，未把 SQLite 复制到客户端，也不代表给学生布置或投递成功。

桌面验收覆盖虚构数据的真实 Electron IPC → 带认证 HTTP → SQLite → 个性化草稿，并检查学生版不包含教师答案；实际服务器接口读到三批 450 题。上线时只重启教师接收端以载入接口，未重启 Hermes 容器或其他服务。

## 原生工具

### 图片清洗与答案核对

规范化题目使用 `format: latex`，`stem`、结构化 `options[{label,text}]`、`answer`、`analysis` 保存文字与 `$LaTeX$`。服务器使用随插件附带的 KaTeX 0.19（MIT 许可证）和 Node 离线生成 MathML，客户端编辑时实时预览。无效公式不能作为正常编辑保存。图形保存在 `figures`，通过 `[[figure:id]]` 引用；图中可识别文字另外转写，示意图本身不伪装成文字。

清洗脚本先恢复原网页的 TeX，再处理只有图片的内容。透明底图片仅在识别输入中铺白底，原图不变。原始版本通过 `cleaning.source_item_id/source_revision` 对照读取；识别输出、每步输入与结果留在服务器运行目录，真实材料不提交 Git。缺图、无法辨认和公式语法问题明确标注，禁止用猜测补全。

答案验证分为不含原答案/解析的独立求解，以及与原答案和解析的比较。独立求解只提供题干与选项中的图，不能看到解析图。`answer_check` 区分机器一致、冲突、不确定、条件不足、修改后失效；机器一致不等于人工审核。原答案不被核对模型覆盖，建议答案与推导独立保存。改动题干、选项、答案或解析后必须重新核对，旧草稿仍按原版本失效。教师版导出包含待核对事项。

脚本顺序：`prepare_question_cleaning.py` → `run_question_recognition.py ... ocr` → `assemble_question_cleaning.py` → `... solve` → 再次 assemble → `... compare`。只有完整覆盖候选数量、来源版本未变化时，`apply_question_cleaning.py ... apply` 才写入版本；先用 snapshot 保存一致的 SQLite 备份及来源版本。中断可恢复，已修改的教师内容不会被覆盖。具体完成数量和核对结论以每次运行的验收报告为准。

`teacher_question_bank` 由插件原生注册，参数中的 `action` 支持：

| action | 作用 |
| --- | --- |
| import | 导入标准 JSON 或有连续题号、答案/解析分段的 DOCX；可设置 expected_count |
| batches / search / read | 列批次，按文字、标签、题型、批次检索，读取当前或历史版本 |
| adapt | 保留母题，创建固定母题版本的改编题 |
| revise | 用 expected_revision 防止覆盖并发修改，保存历史并使依赖产物过期 |
| compose / paper | 固定题目版本和任务提示，生成学生版、教师版及 manifest；读取草稿状态 |
| attempt | 保存作答、帮助情况和评价记录；不自动推断掌握度 |

调用示例（题目、学生及证据 ID 必须替换成工具返回的真实 ID）：

```json
{"action":"search","query":"充分","limit":10}
```

```json
{"action":"compose","title":"个性化练习草稿","purpose":"练习双向推理","selections":[{"item_id":"返回的题目ID","revision":1,"task":{"instruction":"先分别判断两个推导方向。","hint":"尝试找反例。","reason":"教师确认的练习目标"}}]}
```

检索当前使用文字子串和标签过滤，不是向量检索。AI 通过查题、读题、改编和组卷工具作选择；数据库保存确定的结果。图片内文字不会自动变成可搜索文本。学生信息来自独立名册；学习依据应传入现有版本化 evidence，不能从一次作答推定掌握度。

原题正文和修订历史保留；改编题固定母题版本。母题修改后，已有依赖作业过期，不能把旧母题版本的派生题当作最新材料组卷。教师版包含答案解析，学生版不包含答案解析。生成只形成草稿，不代表审核、发布或投递成功。

## 导入和验证边界

`scripts/normalize_question_export.py` 将已保存的网页 DOM 和题图转为 JSON，不联网下载。缺图、缺解析等问题保存在题目 warnings 中，标记 needs_attention。其余题默认 unreviewed，不能视为教学正确性已验证。DOCX 导入器仅处理明确支持的结构，复杂公式可能需要核对。

2026-10-14 实测导入三批智学网候选，各 150 题，共 450 个独立题目：常用逻辑用语、集合、一元二次方程和不等式。其中分别 4、41、7 题待核对，总计 52 题；其余也尚未人工审核。官方 Word 下载被浏览器阻止，本次使用网页内容与题图导出，不能声称官方 Word 已完成下载验证。

验证包括：Windows/Linux 各 10 项题库测试、既有工作台 27 项测试；真实材料重复入库、查找、改编、修订、旧版失效、SQLite 完整性；独立测试目录中两名虚构学生的作业和作答记录。真实 Hermes 运行入口调用 batches/search 返回三批各 150 题及“充分”检索 73 个命中。未进行真实学生课堂验收，DOCX 仅通过合成文件测试。

`ops/deploy_question_bank.py` 用于本次定向部署，变更前备份 SQLite 和涉及文件。未更改 Hermes 核心或发布 EXE。备份恢复测试仅使用虚构测试库；生产库已备份，未做破坏性恢复演练。
